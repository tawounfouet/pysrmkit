## Scope mapping

The Domain model remains:

~~~text
QualificationScope
├── organization_id: optional
├── category_code: optional
└── country_code: optional
~~~

At least one dimension is mandatory.

Relational uniqueness introduces a portability problem because nullable columns do not provide the exact same uniqueness semantics needed for the business rule.

The persistence adapter therefore uses:

~~~text
absent Domain dimension
        ↓
empty persistence string
        ↓
unique comparison is deterministic
        ↓
mapper reconstructs None
~~~

This representation is strictly persistence-internal.

## Non-empty scope constraint

The database independently rejects:

~~~text
organization = ''
category     = ''
country      = ''
~~~

through a CHECK constraint.

The Domain already rejects an empty QualificationScope, so the database acts as a second integrity boundary rather than replacing Domain validation.

## Current-scope uniqueness

The Domain defines:

~~~text
is_current
    = status not in {REVOKED, EXPIRED}
~~~

The SQL model mirrors this rule using a partial unique index on:

~~~text
relationship_id
scope_organization_id
scope_category_code
scope_country_code
~~~

for rows whose status is not:

~~~text
REVOKED
EXPIRED
~~~

This means:

~~~text
same Relationship + same Scope + current status
    -> duplicate rejected

expired/revoked history + same Scope + new current Qualification
    -> allowed
~~~

Both SQLite and PostgreSQL qualify this behavior.

## Explainable QualificationDecision persistence

The root record stores:

~~~text
decision_approved
decision_resulting_status
decision_decided_at
~~~

while ordered child rows store:

~~~text
reasons[]
failed_requirements[]
~~~

This preserves the Domain result:

~~~text
QualificationDecision
├── approved
├── resulting_status
├── reasons
├── failed_requirements
└── decided_at
~~~

No JSON blob is used for first-Core decision state.

## Decision structural integrity

A database CHECK constraint requires decision root columns to be:

~~~text
all absent
or
all present
~~~

This prevents partially persisted decisions such as:

~~~text
approved = True
resulting_status = NULL
decided_at = NULL
~~~

Domain validation remains responsible for semantic consistency such as approved → QUALIFIED.

## Repository contract

The existing shared contract now executes against:

~~~text
SupplierQualificationRepositoryContract
├── InMemory
├── SQLAlchemy / SQLite
└── SQLAlchemy / PostgreSQL
~~~

The contract gained a default no-op:

~~~text
prepare_qualification(qualification)
~~~

SQL harnesses use it only to prepare the required external Relationship FK context.

`SqlAlchemySupplierQualificationRepository` itself never creates parent Relationships.

## Repository semantics

The SQL repository remains Session-scoped and does not commit.

~~~text
save(...)
    -> stage root + owned state

get(...)
    -> reconstitute Domain Aggregate

find_current_for_scope(...)
    -> exact Relationship + normalized Scope
       excluding REVOKED/EXPIRED
~~~

Transaction ownership remains outside the Repository.

## CI security hygiene

The PostgreSQL CI container previously used a static test password literal.

Although it was only an ephemeral local CI credential, secret scanning correctly treated the literal as suspicious.

The workflow now uses:

~~~text
POSTGRES_HOST_AUTH_METHOD=trust
~~~

inside the isolated GitHub Actions service container, and the test URL carries no password.

This removes the hardcoded credential from the current workflow while keeping the PostgreSQL service ephemeral and CI-local.

Production authentication policy is unaffected.

## Implementation feedback

The milestone exposed four useful implementation details:

1. Ruff required import/format normalization in the new integration tests.
2. Pytest exposed a duplicate module basename between SQLite and PostgreSQL Qualification constraint files; the PostgreSQL module received an explicit backend-qualified filename.
3. Optional scope dimensions required a persistence-specific normalization strategy so uniqueness does not depend on NULL semantics.
4. CI secret scanning exposed that even test-only password literals create unnecessary repository hygiene noise; the PostgreSQL service moved to ephemeral trust authentication.

None required changing the Domain model or Repository Port APIs.
