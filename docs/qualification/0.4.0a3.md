across InMemory, SQLite and real PostgreSQL with one shared, deterministic
behavioral contract, explicit Unicode limitations and evidence-based SQL

**not** introduce a new Supplier domain model, public search endpoint,
search engine, schema migration or database index.

## 3. Behavioral guarantees established

The single shared contract uses 13 deterministic Supplier records with
stable UUIDs and 18 named ASCII cases. It runs on InMemory, SQLite and
PostgreSQL and covers:

- Case-insensitive ASCII substring matching in legal and trading names.
- Exact country and supplier-type filters, including absent values.
- SQL `%` / `_` treated literally, not as user-supplied wildcards.
- Filtered total **before** pagination; empty pages, partial pages, offsets.
- Stable case-insensitive ASCII legal-name ordering and UUID ascending
  tie-breaks, including descending-name sort.
- Canonical entity / external identifier preservation and query-only
  Domain Event behavior.
- Unchanged `list_suppliers()` UUID ordering and public `list()` contract.

The public `SupplierPageView` remains immutable. Neither
`SupplierSearchService` nor the runtime composition API was expanded
during this qualification milestone.

## 4. Unicode & collation limits - ADR 24

The **portable guarantee is intentionally scoped to ASCII search and
ordering**. Search and sort behavior for non-ASCII names may vary between
adapters and SQL locale/collation settings.

| Probe | InMemory | SQLite | PostgreSQL 18 (tested CI locale) |
| --- | --- | --- | --- |
| `Straße` vs `STRASSE` | Matches | No match | No match |
| `Étoile` vs `étoile` | Matches | No match | Matches |
| `Café` vs `cafe` | No match | No match | No match |
| NFD `Cafe\u0301` vs NFC `Café` | No match | No match | No match |
| `İSTANBUL` vs `istanbul` | No match | No match | Matches |

This is **observed CI behavior**, not a promise about every PostgreSQL
locale or ICU configuration. No false Unicode equivalence was asserted.
Full Unicode portability would require a separate product decision,
versioned normalized keys, persistence and migration policy, backfill,
indexes and a shared normative Unicode corpus.

Sources: [ADR 24](../specifications/24_PYSRMKIT_SUPPLIER_SEARCH_UNICODE_COLLATION_POLICY.md);
[CI #241](https://github.com/tawounfouet/pysrmkit/actions/runs/40886646863).

## 5. Query plans and performance limits - ADR 25

The SQLAlchemy repository's **actual** filtered count and ordered page
queries were captured and explained on SQLite and PostgreSQL 18, using
1,200 deterministically generated rows and three search scenarios.

| Scenario | Matches / page | SQLite plan | PostgreSQL 18 plan |
| --- | --- | --- | --- |
| Unfiltered | 1,200 / 25 | PK covering scan for count; scan + temporary sort for page | Seq Scan for count; Seq Scan + Sort for page |
| `atlas` substring | 382 / 25 | Scan for count/page, temporary page sort | Seq Scan for count/page, Sort |
| `atlas` + FR + MANUFACTURER | 26 / 6 | Scan for count/page, temporary page sort | Seq Scan for count/page, Sort |

The unfiltered SQLite count can leverage the implicit primary-key covering
index, whereas filtered searches use scans in this fixture. PostgreSQL
estimated 4 vs 382 substring matches and 1 vs 26 combined-filter matches.
This is a **selectivity-estimation observation**, not proof that an index
would speed up the workload.

No additional index, extension, benchmark threshold, performance SLA or
Alembic migration was introduced. Realistic distributions and repeated
timings are required before a production performance optimization.

Sources: [ADR 25](../specifications/25_PYSRMKIT_SUPPLIER_QUERY_PLAN_AND_INDEX_QUALIFICATION.md);
[CI #247](https://github.com/tawounfouet/pysrmkit/actions/runs/40911818953);
[CI #248](https://github.com/tawounfouet/pysrmkit/actions/runs/40912018427);
[main CI #249](https://github.com/tawounfouet/pysrmkit/actions/runs/40912422836).

## 7. Design-learning synthesis

- **Contract Testing / LSP:** reuse one independent oracle for
  substitution of Supplier query adapters, without promising unsupported
  Unicode behavior.
- **DIP / ISP / Ports & Adapters:** tests exercise the existing search Port
  and repository interface without adding adapter dependencies to Domain.
- **CQRS-lite / Immutable Views:** reads remain observational and stable.
- **Deterministic fixtures / Regression Testing:** fixed IDs, named cases,
  stable page expectations and compatibility assertions.
- **ADR / SoC:** Unicode policy and query performance are separate decisions
  rather than accidental domain behavior.
- **KISS / YAGNI / Evidence-Based Design:** no speculative persistence
  changes or performance SLA based on a small synthetic dataset.
