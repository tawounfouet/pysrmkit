# PySRMKit — 0.1.0a3 Supplier Relationships Qualification

**Milestone:** `0.1.0a3 — Supplier Relationships`  
**Qualification date:** 2026-10-27  
**Status:** QUALIFIED / GREEN ON PR

## Business sentence

> **A canonical Supplier can have an independently persisted relationship with an internal organization.**

## Goal

This milestone separates:

```text
Supplier
```

from:

```text
SupplierRelationship
```

A Supplier represents the canonical supplier identity.

A SupplierRelationship represents the contextual relationship between that Supplier and one internal organization.

## Domain scope

Implemented:

- `SupplierRelationshipId`
- `InternalOrganizationId`
- `SupplierRelationship`
- `SupplierRelationshipCreated`

The Aggregate references other Aggregates/contexts by typed IDs:

```text
SupplierRelationship
├── SupplierRelationshipId
├── SupplierId
└── InternalOrganizationId
```

## Initial state

A newly created Relationship exposes:

```text
DISCOVERED
```

No lifecycle transition behavior is implemented in this milestone.

This is intentional: the formal `SupplierLifecycleStage` model and transition guards belong to `0.1.0a4 — Relationship Lifecycle`.

## Rules made executable

### REL-001

A Relationship references exactly one Supplier and one InternalOrganization.

### REL-002

The tuple:

```text
SupplierId + InternalOrganizationId
```

is unique for relationship creation.

The Aggregate cannot enforce cross-instance uniqueness alone.

The rule is therefore coordinated by:

```text
CreateSupplierRelationshipHandler
        +
SupplierRelationshipRepository
```

## Repository Port

Implemented:

```text
SupplierRelationshipRepository
```

with:

```text
get
save
find_for_supplier_and_organization
```

## Adapter

Implemented:

```text
InMemorySupplierRelationshipRepository
```

The adapter stores a persistence-like snapshot and reconstructs a fresh Aggregate on read.

## Application flow

Implemented:

- `CreateSupplierRelationship`
- `CreateSupplierRelationshipHandler`
- `CreateSupplierRelationshipResult`

The Handler:

1. loads the Supplier through `SupplierRepository`;
2. raises `SupplierNotFound` if the Supplier does not exist;
3. checks the Supplier/organization tuple through `SupplierRelationshipRepository`;
4. raises `RelationshipAlreadyExists` on duplicate;
5. creates a new `SupplierRelationshipId`;
6. creates the Aggregate in `DISCOVERED`;
7. saves it;
8. dispatches `SupplierRelationshipCreated`;
9. returns the created Relationship ID.

## Repository contract

The shared contract verifies:

- save/get round trip;
- unknown Relationship ID returns `None`;
- lookup by Supplier + organization;
- unrelated organization does not match;
- different Suppliers remain isolated;
- same Supplier can have independent Relationships across multiple organizations.

## Multi-organization invariant

The critical scenario is executable:

```text
Supplier S
│
├── Relationship R1 → Organization A
│
└── Relationship R2 → Organization B
```

The two Relationships have distinct identities and are independently persisted.
