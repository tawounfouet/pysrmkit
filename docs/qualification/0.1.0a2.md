## Goal

The milestone introduces the first real PySRMKit Aggregate Root:

```text

```

```text
Application
    ↓
Ports
```

## Implemented Domain scope

### Value Objects

- `SupplierId`
- `SupplierIdentity`
- `ExternalIdentifier`
- `CountryCode`
- `Address`
- `CategoryCode`
- `CapabilityCode`

### Aggregate Root

- `Supplier`

Supported behavior:

- create/register Supplier;
- add external identifier;
- reject duplicate identifier inside the Aggregate;
- update allowed identity information;
- preserve Entity equality through `SupplierId`;
- reconstitute persisted state without emitting creation events.

### Domain Events

- `SupplierCreated`
- minimal `DomainEvent` Protocol;
- Aggregate event recording;
- `pull_events()` with queue clearing.

## Ports

- `SupplierRepository`
- `Clock`
- `DomainEventDispatcher`

The Repository Port exposes only use-case-driven methods:

```text
get
save
find_by_external_identifier
```

## Adapters

- `InMemorySupplierRepository`
- `SystemClock`
- `FixedClock`

The InMemory repository stores a persistence-like snapshot and reconstitutes a fresh Aggregate on reads.

This is intentional: a mutation that is not followed by `save()` must not leak into repository state.

## Application flow

Implemented:

- `RegisterSupplier`
- `RegisterSupplierHandler`
- `RegisterSupplierResult`

The Handler:

1. converts primitive command values into Value Objects;
2. checks cross-Supplier external-identifier uniqueness through the Repository Port;
3. creates a stable `SupplierId`;
4. invokes `Supplier.create(...)`;
5. saves the Aggregate;
6. pulls and dispatches recorded Domain Events;
7. returns the created `SupplierId`.

## Repository contract

The shared SupplierRepository contract verifies:

- save/get round trip;
- unknown id returns `None`;
- update + explicit save + reload;
- `find_by_external_identifier`;
- unknown external identifier returns `None`;
- multiple Suppliers remain isolated;
- unsaved Aggregate mutations do not leak into stored state.

The contract is executed against:

```text
InMemorySupplierRepository
```

and is intended to be reused by future persistence adapters.

## Implementation-discovered adjustments

The implementation surfaced several concrete feedback points:

1. Pyright strict required explicitly typed dataclass collection factories for the Aggregate's internal lists.
2. Shared Repository contract tests needed an actual Python package boundary under `tests/contracts/repositories/`.
3. The InMemory adapter must reconstitute Aggregates rather than return the same mutable instance, otherwise missing `save()` calls would be hidden.

These are implementation-driven refinements; none changes the Supplier-domain boundaries defined by the pre-implementation baseline.
