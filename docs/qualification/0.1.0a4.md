# PySRMKit — 0.1.0a4 Relationship Lifecycle Qualification

**Milestone:** `0.1.0a4 — Relationship Lifecycle`  
**Qualification date:** 2026-10-27  
**Status:** QUALIFIED / GREEN ON PR

## Business sentence

> **A SupplierRelationship can move from creation to onboarding through explicit, guarded domain transitions.**

## Goal

This milestone makes the lifecycle of a Supplier relationship executable inside the `SupplierRelationship` Aggregate Root.

The lifecycle belongs to:

```text
SupplierRelationship
```

not to the canonical:

```text
Supplier
```

## State representation

Implemented:

```text
SupplierLifecycleStage
```

as a Python `StrEnum`.

Reference values retained from the invariant baseline:

```text
DISCOVERED
PROSPECTIVE
INVITED
ONBOARDING
UNDER_REVIEW
QUALIFIED
ACTIVE
SUSPENDED
BLOCKED
INACTIVE
OFFBOARDED
```

The Enum represents states only.

It does not implement the State Pattern.

## Implemented lifecycle slice

The first executable path is intentionally small:

```text
DISCOVERED
    │
    │ invite()
    ▼
INVITED
    │
    │ start_onboarding()
    ▼
ONBOARDING
```

The reference baseline also allows:

```text
PROSPECTIVE → INVITED
```

so `invite()` accepts `PROSPECTIVE` as a valid source.

For the first local qualification path, PySRMKit adopts the allowed business-policy option:

```text
DISCOVERED → INVITED
```

This satisfies the milestone exit gate without prematurely implementing a separate prospective-use-case.

## Guard model

The Aggregate does not expose arbitrary lifecycle mutation.

Application code does not perform:

```python
relationship.stage = SupplierLifecycleStage.ONBOARDING
```

Instead:

```python
relationship.invite(occurred_at=...)
relationship.start_onboarding(occurred_at=...)
```

Each behavior verifies the current source stage before changing state.

Forbidden transitions raise:

```text
InvalidLifecycleTransition
```

which carries:

```text
source stage
target stage
```

## Transition reason

Implemented:

```text
LifecycleTransitionReason
```

as a non-blank immutable Value Object.

It is deliberately not forced into invitation/onboarding because the source specification identifies it as particularly relevant to later operations such as:

```text
SUSPENDED
BLOCKED
OFFBOARDED
REACTIVATED
```

Those operations are not part of `0.1.0a4`.

## Domain Events

Implemented:

```text
SupplierInvited
SupplierOnboardingStarted
```

### SupplierInvited

Carries:

```text
event_id
relationship_id
supplier_id
occurred_at
```

### SupplierOnboardingStarted

Carries:

```text
event_id
relationship_id
occurred_at
```

The onboarding entity/identifier remains deliberately deferred to `0.1.0a5`.

## Application commands

Implemented:

```text
InviteSupplierRelationship
StartSupplierOnboarding
```

Matching handlers:

```text
InviteSupplierRelationshipHandler
StartSupplierOnboardingHandler
```

Both handlers:

1. load the targeted Relationship;
2. raise `SupplierRelationshipNotFound` if absent;
3. invoke the Aggregate behavior;
4. save the Aggregate;
5. pull and dispatch Domain Events.

Handlers do not assign lifecycle state directly.

## Repository persistence

`InMemorySupplierRelationshipRepository` now snapshots:

```text
relationship_id
supplier_id
organization_id
stage
```

and reconstitutes the Aggregate with the persisted stage.

The shared repository contract now proves:

- lifecycle state survives explicit save/reload;
- an unsaved lifecycle mutation does not leak into storage.

## State-machine tests

### Allowed transitions

Validated:

```text
DISCOVERED → INVITED
PROSPECTIVE → INVITED
INVITED → ONBOARDING
```

### Forbidden invitation sources

Representative tested sources:

```text
INVITED
ONBOARDING
UNDER_REVIEW
ACTIVE
OFFBOARDED
```

### Forbidden onboarding sources

Representative tested sources:

```text
DISCOVERED
PROSPECTIVE
ONBOARDING
UNDER_REVIEW
ACTIVE
OFFBOARDED
```

For every failed transition:

```text
state unchanged
+
no success event recorded
```

## Multi-organization isolation

The same Supplier may still have independent Relationships:

```text
Supplier S
│
├── R1 / Org A → ONBOARDING
│
└── R2 / Org B → DISCOVERED
```

Transitioning R1 does not change R2.

## Implementation-discovered adjustments

The implementation did not require a new architecture abstraction.

One formatting-only CI adjustment was made after Ruff requested a one-line formatting change in a lifecycle handler test.

The more important design confirmation was that:

```text
Enum + explicit Aggregate guards
```

is sufficient for this milestone.

No GoF State Pattern is justified by current behavior pressure.
