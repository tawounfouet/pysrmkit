## Decision: retain the legacy dashboard contract

Inspection of `tawounfouet/nextjs-acme-dashboard` on its default branch:

- `app/dashboard/suppliers/page.tsx` calls `fetchSuppliers(offset, 25, query)`.
- `app/lib/data.ts` constructs **`new URL('/suppliers', apiUrl)`**,
  sets `offset`, `limit`, and optional `query`, then fetches the
  legacy endpoint with `cache: 'no-store'`.
- `app/ui/suppliers/table.tsx` renders supplier names, vendor code,
  supplier type and country, and advertises a search for suppliers,
  country or vendor code.
- `examples/http_api.py` intentionally keeps this legacy text-search
  behavior while exposing `GET /suppliers/search` as an opt-in,
  name-only canonical search.

**A4-04 does not migrate the Next.js consumer.** Replacing the dashboard
URL with `/suppliers/search` would silently remove searches by vendor
code and country, which are currently part of the dashboard UX.

## End-to-end evidence

The existing real-stack browser test in `tests/test_browser_journey.py`
already checks login, navigation, eight demo suppliers, name filtering,
clear and refresh. A4-04 extends **that same E2E journey** to verify:

1. Real HTTP `GET /suppliers?query=SUP-008` returns Helios Data Oy.
2. Real HTTP `GET /suppliers/search?query=SUP-008` returns no matches.
3. Real HTTP `GET /suppliers?query=FI` returns Helios Data Oy by country.
4. Real HTTP `GET /suppliers/search?query=FI` returns no matches.
5. Browser input `SUP-008` renders exactly Helios Data Oy and one row.
6. Clearing the search restores all eight seeded suppliers.
7. The existing legal-name search, clear and refresh flow remains unchanged.

The test operates against live FastAPI, PostgreSQL, Next.js and a
Playwright Chromium browser in the existing `integration` CI job.
It guards the **observable consumer behavior**, not an implementation
detail or a duplicated mock of the dashboard's data-fetching function.

## Reproducibility and limitations

CI checks out `tawounfouet/nextjs-acme-dashboard` on its current default
branch. As this is an unpinned external repository, the integration
test qualifies the revision GitHub Actions checked out in that run;
its evidence does **not** establish compatibility with all historical
or future dashboard versions. Pinning an explicit dashboard SHA and
updating it through a controlled compatibility PR is a possible future
reproducibility enhancement.

The legacy `query` path performs an in-process scan and should not be
presented as a production-scale search SLA. The canonical route's
ASCII-only portable search policy, Unicode limitations and SQL plan
observations remain unchanged.

No changes to the external dashboard repository, PySRMKit Core,
schema, indexes, package version or mandatory runtime dependencies.

## Design concepts

- **Consumer-Driven Contract Testing:** test the search behavior a real
  consuming application relies upon.
- **Ports & Adapters / Anti-Corruption Layer:** legacy HTTP semantics are
  deliberately distinct from the canonical Python Supplier search Port.
- **Expand-and-Contract:** retain a legacy interface while publishing an
  opt-in canonical endpoint.
- **Regression Testing:** verify existing navigation, refresh and search
  behavior under a genuine browser and database.
- **KISS / YAGNI:** no premature migration or transport abstraction.
